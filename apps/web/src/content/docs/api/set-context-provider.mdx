Use `setContextProvider()` when command resolution needs explicit app state that does not live in semantic tags alone.

## Example

```ts
Cinder.setContextProvider(() => ({
  accountId: currentAccount.id,
  region: currentRegion,
}));
```

You can also return a promise:

```ts
Cinder.setContextProvider(async () => {
  return {
    accountId: await getSelectedAccountId(),
  };
});
```

## Important behavior

- `resolve()` uses a synchronous provider result when available, otherwise it uses cached context
- `run()` awaits fresh async context before local resolution happens
- fallback requests can also include the injected runtime context
