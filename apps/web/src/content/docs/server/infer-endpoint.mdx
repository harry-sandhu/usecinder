The main fallback endpoint is `/v1/llm/infer`.

## Endpoint

```http
POST /v1/llm/infer
Authorization: Bearer <API_KEY>
Content-Type: application/json
```

The bearer token is only required when the server is configured with an API key.

## What the server validates

Before provider inference runs, the server validates and normalizes the request body.

Invalid infer requests return:

```http
400 Bad Request
```

## Request shape

The browser can send normalized input like:

```json
{
  "text": "show soybean prices in punjab",
  "context": {
    "activeRoute": "reports",
    "activeContext": "crop-prices",
    "region": "north"
  },
  "graph": {
    "activeRoute": "reports",
    "activeContext": "crop-prices",
    "routes": ["reports", "farmers"],
    "contexts": ["crop-prices", "registration"],
    "filters": ["crop", "state"],
    "actions": ["search"],
    "outputs": ["price"],
    "selections": {
      "crop": "soybean"
    }
  },
  "app": {
    "route": "reports",
    "version": "0.1.0"
  },
  "options": {
    "generateReply": true,
    "temperature": 0.2
  }
}
```

## Response shape

The server returns normalized structured output so the browser runtime can keep using the same dispatch model.

```json
{
  "intent": "composite_flow",
  "confidence": 0.82,
  "steps": [
    { "type": "set_filter", "target": "crop", "value": "soybean" },
    { "type": "set_filter", "target": "state", "value": "punjab" },
    { "type": "trigger_action", "target": "search" }
  ],
  "entities": {
    "crop": "soybean",
    "state": "punjab"
  },
  "reply": "Showing soybean prices in Punjab.",
  "source": "cloud"
}
```

## Error cases

### Invalid request body

```http
400 Bad Request
```

### Unauthorized when API key is configured

```http
401 Unauthorized
```

### Invalid provider output or provider failure

```http
502 Bad Gateway
```

This is important because the browser runtime should not assume every provider response is usable.

## Why normalization matters

<Callout variant="info" title="Same dispatch model">
  Cloud output should still become a dispatchable local intent shape. That keeps the browser runtime coherent and preserves the local execution model instead of creating a second execution system.
</Callout>

## Important browser-side note

A valid server response can still be rejected by the browser runtime if it cannot be safely grounded to the real graph or if duplicate targets are ambiguous.
