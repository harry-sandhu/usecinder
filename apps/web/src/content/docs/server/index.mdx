<Callout variant="warning" title="Optional package">
  `@cinder/server` supports hybrid fallback mode, but it is not required for local-only usage. The browser runtime is still the product core.
</Callout>

`@cinder/server` exists to help when local resolution is unknown or low-confidence and the app has explicitly enabled fallback.

## Why the server exists

The server handles fallback inference and returns **normalized structured results** that the client can ground back into the same local dispatch pipeline.

That means the server is responsible for:

- validating the infer request body
- enforcing optional bearer auth
- delegating to a provider adapter
- normalizing the provider response shape
- returning a result the browser can safely normalize against the real graph

## What the server is not trying to do

The server is **not** replacing the browser runtime.
It should not hide:

- weak semantic tagging
- broken graph structure
- ambiguous duplicate targets
- poor local route/context clues

Those are usually browser-runtime issues first.

## Current server truth

The current server includes a provider factory and a working heuristic adapter. That proves the fallback architecture and normalized contract, but it is not the final provider strategy for every production deployment.
