Use `@cinder/server` only when you want bounded fallback inference.

<Callout variant="tip" title="Don't want to run your own server?">
  `@cinder/relay` speaks the exact same fallback contract, hosted and metered - a usage-based alternative to self-hosting this package. See <a href="/docs/relay">Relay Overview</a>.
</Callout>

## Start the server

The server package exposes a Fastify-based service layer for health and infer endpoints.

At a high level, the server is responsible for:

- receiving normalized infer requests
- validating request shape
- delegating to a provider adapter
- normalizing provider responses
- returning structured results the browser can ground back into the app graph

## Configure the client

```ts
await Cinder.init({
  semantic: {
    scanOnInit: false,
    observeMutations: true,
  },
  ai: {
    enabled: true,
    mode: 'hybrid',
    endpoint: 'http://127.0.0.1:8093/v1/llm/infer',
    apiKey: '',
    provider: 'custom',
    timeoutMs: 10000,
  },
});
```

## Verify the server path

Test:

- `/health`
- `/v1/llm/infer`

Then run a request likely to miss the local resolver and inspect:

- `fallback:start`
- `fallback:end`
- whether the normalized result was actually usable

## Important boundary

The server is there to support the local runtime, not replace it.

If the local path is still weak because tags, graph shape, or active-state clues are wrong, fallback should not be your first fix.
