Runtime context is the right place for app state that matters to intent selection but does not belong in semantic tags.

## Typical example

```ts
Cinder.setContextProvider(() => ({
  accountId: selectedAccountId,
  region: selectedRegion,
}));
```

## Async example

```ts
Cinder.setContextProvider(async () => {
  return {
    accountId: await getSelectedAccountId(),
  };
});
```

## Good use cases

- current account or tenant
- selected region
- workflow state
- app-specific environment values

## Practical note

Use `Cinder.getContext()` to inspect what the runtime currently sees.
