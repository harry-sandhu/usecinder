## What the docs assume

<Callout variant="tip" title="The core product promise">
  These docs assume the V1 promise is: install Cinder, tag a website you control, resolve common navigation/action/field/output flows locally, and use custom bindings or adapters only when the standard DOM path is not enough.
</Callout>

## What is true about the current SDK

- the browser runtime is the product core
- semantic tags and graph structure are primary, not prompt tricks
- local-first resolution is the default path
- fallback is optional, bounded, and secondary
- ambiguity is handled more honestly than earlier MVP versions
- extension points now exist for routes, DOM adapters, custom intents, runtime context, and runtime events
