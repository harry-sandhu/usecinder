## Good first examples to build

### 1. Dashboard/reporting app
Use:

- one route
- one filters context
- one search action
- one output surface

### 2. CRUD form flow
Use:

- one route
- one form context
- fields
- one save action
- native submit behavior

### 3. Table/filter/result flow
Use:

- one route
- repeated data regions
- filters
- output or data surfaces
- active context awareness

### 4. Speech-enabled field entry flow
Use:

- text-first path proven already
- `listen({ autoRun: false })`
- transcript/error hooks

### 5. Hybrid local + fallback flow
Use:

- local-first path already working
- server health verified
- infer endpoint wired
- fallback telemetry observed

## Example design rules

A good example should include:

- one real route
- one semantic context
- at least one action
- one output or data surface
- easy-to-inspect DOM structure
- no unnecessary fallback dependency in the first proof
